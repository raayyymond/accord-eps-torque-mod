WHAT A FAIL WOULD HAVE LOOKED LIKE (written before the runs):
  - regime B dies if |H| collapses toward 1 under a different estimator, taper, detrend or window
    length, or if the excess piles at the top band edge (leakage from 1.2-2.4 Hz).
  - the budget dies if (X->Z) + (Z->Y) does not sum to (X->Y).
  - the whole comparison dies if wheel -> yaw differs between builds at matched speed.

=========================================================================================== 4. CONTROL
Wheel -> yaw, the pure-vehicle control, PASSES where it matters.  Speed-matched 2 m/s bins, H1 ratio
TORQ/V282 at 0.15-0.30 Hz: 1.29 / 0.98 / 0.87 / 1.08 / 0.93 / 1.37 / 1.04 / 0.99 / 1.03 (v 6-30).
At 0.30-0.60: 1.14 / 1.06 / 0.92 / 1.00 / 0.95 / 1.10 / 0.94 / 1.04 / 0.98.  Route level, 16-22 m/s,
0.15-0.60 Hz: +5.9%, exact permutation p = 0.42.  No comparison error upstream.
IT DOES NOT PASS at 0.60-1.20 and 1.20-2.40 Hz (ratio 0.55 at 20-22 m/s, 0.70 at 28-30, brackets
[H1,H2] disjoint).  H1 is biased DOWN by input noise and torque mode puts x3-5 more 1.8-3.5 Hz motion
on the wheel, so part of this is estimator; part is real (wheel motion that does not reach the road).
Either way the vehicle is NOT a common reference above ~0.6 Hz, which is exactly regime B's band.
A stream that reports wheel->yaw differing between builds is therefore not automatically wrong -- but
it must show the [H1, H2] bracket and match speed within 2 m/s before calling it a plant difference.

======================================================================================= 5. MY OWN LIMITS
- I use NON-overlapping windows, so my window counts are ~40% of the surface stream's.  Overlapping
  windows add resolution, not independence, and cannot repair a one-route reference -- but my absolute
  |H| values will differ slightly from theirs for this reason.
- My route-level tests have 3 V282 routes, so the minimum attainable two-sided p is 2/220 = 0.009.
  "p = 0.196" means the data cannot resolve it, not that the effect is zero.
- I did not re-derive the AccordRefFilter identification from the fork source; I confirmed its 2*RC
  signature from the logged X->Z lag only.
