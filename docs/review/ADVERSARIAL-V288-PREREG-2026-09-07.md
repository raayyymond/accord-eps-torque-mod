## What a FAIL looks like (any one ⇒ DO NOT FLASH)
1. **Arithmetic/encoding (A):** any new instruction decodes differently from the builder's listing under an independent decoder or Ghidra on the BUILT image; either `jr` displacement lands anywhere but 0xC4BDC (hook) / 0x29D76 (return) / 0xC4C00 (0x14A exit); the filter can leave y ≠ sp at steady state, stick at a non-zero LSB, overflow 16 bits, or corrupt r10/r26/lp/PSW-dependent control flow at 0x29D7E.
2. **Units/scale & loop (B):** the sp Q-format or range at the hook is not what the cave assumes; the filter changes the feedback return ratio (anything downstream reads gp-0x6a32 or raw sp); the added lag (15 ms at K=4) provably consumes the openpilot outer-loop phase margin below unity-safe, or exceeds the actuator delay openpilot already models (SteerDelay 0.2 s); engage/disengage transients produce a setpoint the raw path could not produce (sign flip, overshoot).
3. **Build-script audit (C):** independent rebuild does not reproduce the hash; full-file diff has any byte outside {0x29D72–75, 0xC4BD6–D9, 0xC4BDC–FD, 0xC4C00–1F, 0xC4FFC–FF}; any CRC in the chain is wrong; more than one flashable V288 rwd; the assertion census hides a false substantive claim.
4. **Interlocks/GATE 1 (D):** gp-0x6a32 (0xFEDF15CE) has any reader or any register-indirect/table-dispatched writer (the 0xb7260 mailbox class); the duplicate PID copy at 0x2A508/0x2AC68 is reachable; 0x29D72/0x29D74/0x29D76 is a branch target from anywhere; the hook runs on a path where r16 is not the assist-map output; a plausibility monitor / DTC / the oscillation detector / EME is provably tripped by a ≤16 ms setpoint lag or by a filtered setpoint that differs from the command by up to one command step.
