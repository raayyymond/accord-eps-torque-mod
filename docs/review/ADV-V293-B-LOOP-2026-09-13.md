## 0. The crux, verified by this agent rather than inherited

Every criterion on this surface rests on one claim: **with `0xC62E6` = 0 the LKAS return ratio is
identically zero at every frequency.** Adversary A established it by simulating the clamp block over
4,023 int32 states. This agent verified it independently, two ways:

1. **Byte diff, this agent's own reader** [EVIDENCE]: V293 vs V282 differ in **378 bytes, all at or above
   `0xC61B7`**; the code region `[0x13000, 0xC0000)` has **zero** differing bytes, and the clamp block
   `[0x28F80, 0x28FE0)` is byte-identical across **stock, V282 and V293**.
2. **The decompiled clamp block itself** (GhidraMCP, `FUN_00028ea6`; `tp = 0xBF000` so
   `DAT_000072e6 + tp` = `0xC62E6`). Mirrored in integer Python, with the instruction the branch belongs to:

```python
C   = u16(0xC62E6)                 # 0x28FA6  ld.hu 0x72e6[tp]      V293: 0
s   = r31 + r34                    #          the two-sample sum (the fb operand)
if s > C:            out = C       #          first conjunct false -> uVar35 keeps C
elif s < -C:         out = -C      #          second conjunct     -> uVar35 = -C
else:                out = s       #          uVar35 = uVar37, set inside the comma expression
E_operand = (out >> 5) * 32        # 0x28FBE  arithmetic shift, then re-scale
```

It is a **symmetric ±C clamp on all three arms**, so `C = 0` forces `out = 0` on every branch, for every
state value, and `E_operand = 0`. **L ≡ 0 at every frequency. [EVIDENCE]**

## 7. B8 — the forced 18–22 Hz response with the loop open (reported)

With `L ≡ 0` the delivered torque is a memoryless function of the command: it cannot grow with wheel

slope and the output lag.
