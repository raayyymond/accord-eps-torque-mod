## What A340 is (EVIDENCE)
A different compile of the same application (build string C30_802_D_12_00, 2020-07-16; A160 is C30_802_D_08_00). Bootloader
handlers (SA key 0xAAB4, decryptor, DID 0xF101 key write, window table) byte-identical; CRC chain layout identical (50 blocks,
main [0x13000,0xC4FFC)); rwd cipher BF/10/9E unchanged. From 0x14000 on, code AND cal are re-laid: NO A160 address carries over.

## Structural differences that matter for the mods (EVIDENCE, lane trace)
1. Kp, Kd, Ki, the rate-reference map and the dir-0 hand fades are SPEED-SCHEDULED RAM tables: `FUN_0002a740` (100 Hz) blends
   3 speed records (knots 4160/5120/12800) × 12 variants = 36 flash records per table into RAM; the lane LERPs the RAM copy.
   All 36 are identical on stock. Any record edit = 36 records.
2. Gain Q-format: P = (E·Kp)>>3 with 8-bit Kp (A160: >>8, Kp up to 696); I increment ((e5·Ki)<<2)>>3 (A160 (e5·Ki)>>3);
   D = (dE·Kd)>>3 (same). Stock Kp 10..21, Kd 32, Ki 0, ICL 0.
3. Stock A340 P/sum clamps 20480 (A160 15360), post-fade clamp 0xC61CA 20476 (new), output lag 1005/324 (DC 1.066; A160 0.990).
4. Lane register use differs at the V300 hook site: r6 (engage state) and r8 (I deadband) are LIVE; E is in r9 (A160 r16).
5. V300's private gain cell 0xC6CD0 is occupied; the only free 0xFFFF run in the 0xC6 block is 0xC6D28..0xC6FEF (host 0xC6E88).
6. Low-speed lockout 0xC62FC is already 0 on stock. STEER_STATUS debounce thresholds 12800/8960/11520 (first cannot trip).
