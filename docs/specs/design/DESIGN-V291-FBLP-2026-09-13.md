## 4. WHY THE GATE CANNOT BE ESCAPED BY THIS CLASS — the mechanism, verified two ways

`gate73(el, el0) = |LS73·R73 + LR73|` with `R73 = el.Rf(7.3)/el0.Rf(7.3)`, `LS73 = 0.55∠+96°` (the
servo arm), `LR73 = 1.19∠−27°` (the r24 pump arm). At `R73 = 1` the two vectors are **nearly orthogonal
and partially cancel**: 0.55∠96° = (−0.058, +0.547), 1.19∠−27° = (+1.060, −0.540), sum (1.003, +0.007),
magnitude 1.0028. **The EPS's own 7.3 Hz rate feedback is currently cancelling most of the r24 pump's
imaginary part.**

### 6.1 The `sar` floor makes the state decay ASYMMETRIC — and this is true of STOCK V282 too

`>>` on V850 is arithmetic (floors toward −∞). With `d = 1024 − a`:
- `s > 0`: decrement = `ceil(d·s/1024) ≥ 1` always — the positive state always decays.
- `s < 0`: decrement = `floor(d·|s|/1024)` = **0 whenever `|s| < 1024/d`** — the negative state **sticks**.

| pole | d | sticks below \|s\| | = raw counts of x | = deg/s at the wheel | resting fb offset |
|---|---|---|---|---|---|
| 16.53 (V282) | 101 | 10.1 | 0.656 | 0.082 | **−20 E-counts** |
| 11.94 | 74 | 13.8 | 0.896 | 0.112 | −26 |
| 7.97 | 50 | 20.5 | 1.326 | 0.166 | −40 |
| 6.02 | 38 | 26.9 | 1.744 | 0.218 | −52 |
| 2.03 | 13 | **78.8** | **5.095** | **0.637** | **−156 E-counts** |

Verified by direct integer simulation (released from `s = −1000` with `x ≡ 0`, 20,000 ticks). At the 2 Hz
pole a resting −156 E-count feedback offset is a phantom demand of 156/32 = 4.9 setpoint counts ≈ 24 counts
of standing motor torque against the 3072 clamp — **×7.8 the stock artefact.** One-sided, in the same
direction, present whenever the wheel is still. [EVIDENCE for the arithmetic; BELIEF for the on-car
consequence, since the closed loop unsticks the state as soon as the wheel moves.]

### A4.1 The structure, and the new class it needs

Low-pass **only** the feedback operand feeding P; leave D on the raw 16.53 Hz-filtered `fb`. P and D then


## B2. (b) THE r24 FOLD MACHINERY — PREPARED, SELF-TESTED, NOT RUN

### B2.1 ⭐ The full family re-run is NOT needed — a closed form replaces it

Let `Lam(z)` be the r24 lane's return ratio per unit **wheel rate** at gain 5244, in the convention
`rate = G0·(u_lkas + r24)`, `r24 = Lam_bar·bar`, `bar = B·rate`, so `Lam = Lam_bar·B`. The family's
fitted `Plant` is the **closed** plant `Gc = G0/(1 − G0·Lam)`. Then

```
1/Gc = 1/G0 - Lam                        =>   G0 = Gc / (1 + Gc*Lam)
1/Gk = 1/G0 - k*Lam = 1/Gc + (1-k)*Lam   =>   Gk = Gc / (1 + (1-k)*Lam*Gc)
```

**The k-scaled plant follows from the fitted plant by one rational operation, and at k = 1 it is the
identity — exactly.** The 304 fits stay valid; only the scoring changes. Step 4 of A6 (the expensive
`family()` + `refine()` re-run) **is cancelled.**

As polynomials in `w = z^-1`: `Gk.num = Gn·Ld`, `Gk.den = Gd·Ld + (1−k)·Ln·Gn`. `PlantK` exposes exactly
the `num` / `den` interface `Lpoly`, `poles_of` and `metrics` already consume, so **no change to
design290b is required at all** — `score_row()` simply wraps each fit.

**From the tracer's facts, if `r24lane` supplies only `B = bar/rate`:**
`Lam_bar(z) = (g/1024)·(1 − z^-4)` with `g = [0xC6446]` — the lag-4 backward difference of torsion-bar
torque at Q10 gain. Built by `lam_bar_poly()`; `lam_from()` composes it with `B`.

## B5. 🛑 THE `gp-0x671d` LATCH — r24 IS BIMODAL ON V282, AND C12/C8's EDIT IS INERT IN ONE MODE

Found in `.claude/agent-memory/firmware-codepath-tracer/reference_accord_gp671d_arm_inverts_r24_on_v280plus_and_6ad4_vs_6b4c_conflict.md`
(agent `r24lane`'s tracer, same day) **after** B1–B4 were written. **I verified the crux from the images
myself before folding it in**, because it bears directly on the working candidate.

### B5.1 The cells, read from the images

| cell | stock | V282 | V289 | role |
|---|---|---|---|---|
| `0xC6446` | **512** | **5244** | 5244 | gain_B, ENGAGED arm — **the cell C12/C8 edit** |
| `0xC6442` | 1024 | **1024** | 1024 | gain_B, `gp-0x671d != 0` arm — **outranks all, and C12/C8 do NOT touch it** |
| `0xC61FA` | 5530 | 5530 | 5530 | Schmitt SET threshold |
| `0xC61F8` | 1024 | 1024 | 1024 | Schmitt RELEASE threshold |
| `0xC61F6` | 3 | 3 | 3 | (deadband) |

All five confirmed by direct `struct.unpack_from('<H', img, addr)` on the stock dump, the V282 image and
the V289 image. **The tracer's reading is correct.**

⇒ **On stock the fault arm DOUBLES r24 (512 → 1024). On V282 it COLLAPSES it (5244 → 1024, ×0.1953).**
The latch is a **first-strike, rising-edge, saturating Schmitt** (SET |x| ≥ 5530, RELEASE |x| < 1024),
and the selector tests `!= 0`, so **one crossing flips the arm for the rest of the drive cycle.**

### B5.2 What it does to C12 and C8 — three consequences, only one of them benign by luck

1. **The edit is INERT in the latched mode.** C12/C8 change `0xC6446` only. If the latch fires, both
   V282 and the candidate run `0xC6442` = 1024 and **the r24 halves of C12 and C8 do nothing at all**,
   while the fb-pole halves stay live. That is the configuration the body of this memo calls
   *"fb 11.94 / 7.97 Hz at k = 1"* — except at k = 0.1953.
2. ⭐ **And that configuration is SAFE, by luck rather than by design.** Scored on the same gate:

   | config | gate, k = 1 | **gate, latched (k = 0.1953)** |
   |---|---|---|
   | V282 | 1.0028 | 0.4661 |
   | C12 | 1.0750 | **0.4636** |
   | C8 | 1.1624 | **0.4465** |

   **The latched mode has ×2 the 7 Hz margin of the unlatched one for every row.** So the latch is not a
   safety hazard for C12 or C8 — but note that the margin then comes **entirely from the latch and not
   from the edit**, which is the opposite of what the build would be cut to demonstrate.
3. 🛑 **IT VOIDS THE BIT-6 PREDICTION IN B3.4.** A latch event drops `|r24|` by **×0.195** regardless of
   the edit, which swamps the −6 % to −40 % the edit is predicted to produce. **The model-free ordering
   `duty_C8 < duty_C12 < 0.1141` holds only if both drives are in the same latch state**, and nothing on
   the wire currently reports that state.

### B5.3 The measured bound, and why the k = 1 baseline survives

Agent `bof` (`rlog-tools/studies/grind/B-OF-F-V282-2026-09-13.md` §5, item 6) measured the arm on **two
V282 routes — r39 (880 s engaged) and r6c (3136 s engaged) — and reports the latch did NOT fire**: the
implied gain reads 2268–2747 in every stratum on both routes against 1023 if latched, the detection
floor is ×0.94 and the hypothesised collapse is ×0.195, i.e. **13× the detection floor**, with the one
"step" found running upward. **[EVIDENCE, `bof`'s, relayed — I did not re-derive it.]**

⇒ **The k = 1 baseline B1–B4 is built on is sound for the routes the model was identified from**, and
the gate_k table stands. What changes is the **pre-registration**, not the scoring.

### B5.4 What must be added to the pre-registration before either row is flown

- **A LATCH CHECK IS NOW MANDATORY ON EVERY DRIVE THAT SCORES C12 OR C8.** `bof`'s estimator is the
  available method. **A drive on which the latch fired cannot score the r24 half of the edit at all**,
  and must be reported as such rather than as a null.
- **Bit 6 falls for two independent reasons** — the edit, and a latch event — and the wire cannot
  currently tell them apart. Either add a rung that reports the latch state (`gp-0x6ad8` is the
  telemetry mirror the tracer found, *"the ONLY touch of `gp-0x6ad8` image-wide"*, computed and stored
  and never read), or accept bit 6 as landed/not-landed only, conditional on the latch check passing.
- ⭐ **A FREE VALIDATION POINT THE KIT HAS NOT USED:** the latched mode is an r24 gain of **1024**, i.e.
  `k = 0.195` — **deeper than anything C12 or C8 propose, on a car the operator has already driven.**
