### 5.4.1 🛑 CAN THE INSTRUMENT ACTUALLY SEE THE EFFECT? — the check V97 skipped

V97 is the case study the kit keeps citing: *a pole with DC gain 1.000000 at every value, so no
amplitude statistic could ever see it.* **The same question must be answered here before cutting.**

Write `in[n]` for `gp-0x6b82`, `out[n] = clamp(H*in)[n] + p[n]` for `gp-0x6b86`, `p` the near-DC
pedestal. The rung is `duty = P(|out| ≥ |in|)`.

1. **Is `duty` monotone in the notch's effect?** Yes. `|H|` is ≈ 0 dB across 0.5–50 Hz
   (band-average **−0.087 dB**) *except* in 6–9 Hz, where it is **−6.55 dB**. So the more of the
   input's energy sits in 6–9 Hz, the more `|out|` falls relative to `|in|`, and the lower the duty.
   **The effect is in the statistic by construction, not by hope.**
2. **Is the operating point away from a rail?** Yes — and this is what kills a V97-style null. A
   near-0 dB broadband filter gives duty near **0.5**, the maximum-sensitivity point of a Bernoulli
   statistic. Had `|H|` been > 1 everywhere, duty would rail at 1.000 and carry no information.
   **[EVIDENCE, the band table in §2.2.]**
3. **Does the pedestal destroy it?** It shifts the *level*, not the *slope*. `p` comes from a
   1.56 Hz-cornered IIR, so across a 1 s window it is effectively constant while the notch's effect
   modulates at the input's own frequency. **A constant offset moves duty up uniformly across
   strata; it does not create a spurious dependence on the input's 6–9 Hz fraction.**
   ⚠ **[BELIEF]** — this holds only if `p` does not itself correlate with the input's band
   composition. **Rung b5 measures `p`'s size directly**, which is the best available guard, and
   readout ② turns a large `p` into a stated, in-drive void rather than a silent bias.
4. **Is the exposure sufficient?** V103's route `0x9e` gave **406.4 s engaged** and V103's own
   comparator rungs resolved duties to ±0.02 against prediction across 32,388 frames. A duty
   difference of even 0.05 between strata is far above that noise floor. **A 15–30 s symptomatic
   episode is enough**, which is the standing requirement.

⇒ **The honest answer to "what if it reads no change?" is a real sentence, not a shrug** — §5.4 ③.
**This instrument passes the gate that V97 failed.**

### 5.8.1 ⭐ WHY THE HOOK PLACEMENT WORKS — and what it permits
Nobody has written this down, and it constrains any new byte the cave might claim.
**[EVIDENCE, strict scan + mask decode on the stock image.]**

```
0x55AAC .. 0x55B06   Honda's THREE byte4 read-modify-writes  (bits 2,1,0)
0x55BF2 .. 0x55C02   Honda's FIRST byte7 read-modify-write   (andi 0x00CF -> bits 5,4)
0x55C0E              <<< THE CAVE HOOK -- jarl 0xC4B34,lp
   cave writes byte4 bits 7:3  and byte7 bits 7:6
0x55C1C .. 0x55C2A   Honda's SECOND byte7 read-modify-write  (andi 0x00F0 -> bits 3:0)

                       identity code survives Honda writing the frame after it.
```

⇒ The hook sits **after every Honda byte4 write** and **inside** Honda's byte7 handling, in the one
place where the surviving mask (`0xF0`) protects the cave's bits. That is why ~50 builds of cave
telemetry work, and it is not luck — but it does mean **any new bit the cave claims must be checked
against every Honda mask that runs after `0x55C0E`.** For **byte 6** there are **zero** byte-width
accesses anywhere in the image, so nothing after the hook can clobber it — the only risk is the wide
`st.w` at `0x21964` (§5.6, Conclusion 3).

## 6. GATE 1 FOR THE COEFFICIENT EDIT — DONE, AND IT IS CLEAN

Nobody was asked for this, but a four-cell edit inside an always-on lane needs it.

**Method [EVIDENCE].** Raw Python LE byte scan of the V103 image for tp-relative accesses
(`tp = 0xBF000`, and `tp == r5` — proven from `0x35A02` = `85 67 fb 74` = `ld.bu 0x74fa[tp],r12`,
whose `hw1 = 0x6785` has `reg1 = 5`), across **both** candidate displacement encodings (`enc` and
`enc|1`, the `ld.bu` odd-displacement form), plus the **6-byte extended-displacement form**
(`disp = (sext16(hw2) << 7) | ((hw1 >> 4) & 0x7F)`), plus a whole-image LE32 absolute-literal search.

🛑 **THIS SCAN WAS WRONG TWICE BEFORE IT WAS RIGHT. BOTH ERRORS ARE RECORDED BECAUSE BOTH ARE
INSTRUCTIVE.**
- **Error 1** — an opcode whitelist `{0x38…0x3B}` omitted `ld.bu` (`0x3C`/`0x3D`), so the control cell
  `0xC64FA` returned **0** against a record claim of ~18. RULE 15: *an implausible null is a bug
  report.* Caught by running the control.
- **Error 2, the important one** — the re-run treated `hw2` as the displacement. For `ld.bu` **the
  displacement's bit 0 lives in the opcode LSB** (`0x3C` = even, `0x3D` = odd) and `hw2` always
  carries `(disp & 0xFFFE) | 1`. Treating `hw2` as the address **silently merges a cell with its
  odd/even neighbour.** Caught only by loading the `firmware-decompile` skill, which names this trap
  exactly: *"an encoder or scan assuming one parity silently addresses the neighbouring cell with
  every other field perfect."*

**Parity rule validated against two byte-exact anchors from the kit's own record** — `0x35A02` =
`85 67 fb 74`, annotated in `builds/v80_v107/build_v103_tva.py` as `ld.bu 0x74fa[tp],r12`, lands in `0xC64FA`'s list;
`0x359FE` lands in `0xC649B`'s and sits inside `FUN_000352b4`. **[EVIDENCE.]**

### 6.2 THE COEFFICIENT→ROLE MAPPING IS CONFIRMED THREE WAYS
If `a1` and `b1` were swapped, the four-cell edit would build a completely different filter. The
mapping (`0xC60A8`=a1, `AC`=a2, `B0`=b1, `B4`=g) is confirmed, not assumed:

1. **It reproduces the independently-recorded stock response to every printed digit [EVIDENCE].**
   Feeding the stock bytes through `H(z) = g(1 + b1 z⁻¹ + z⁻²)/(1 + a1 z⁻¹ + a2 z⁻²)` gives
   pole `|z| = 0.796630` at **42.345 Hz**, zero `|z| = 1.000000` at **55.225 Hz**, peak `|H|` =
   **+0.0003 dB**, and **−1.549 dB / −33.21°** at 23 Hz — matching the agent-memory values
   (`reference_accord_biquad_is_a_notch_v103_armed_and_recentering_priced_short`), which were derived
   twice, independently, by a different agent from its own disassembly.
2. **The swapped mapping is refuted by construction:** it yields a pole at `|z| = 1.440` — a
   divergent filter Honda could not ship.
3. **The instruction load ORDER corroborates the roles [EVIDENCE, validated tp-scan]:**
   `0x35A30` loads **g**, `0x35A40` **a1**, `0x35A44` **a2** — the recursion
   `w[n] = g·u[n] − a1·w[n−1] − a2·w[n−2]` — and only later, at `0x35A58`, **b1**, the FIR term in
   `y[n] = w[n] + b1·w[n−1] + w[n−2]`. Interleaved with the state accesses at `0x35A2C`, `0x35A4C`,
   `0x35A64`, `0x35A6A` that V103's own script already asserts.

⇒ **the numerator's outer coefficients are hardcoded 1.0 (bare adds, no multiply), so the zeros lie
exactly on the unit circle by Vieta — a TRUE notch, at every coefficient value.** That is why the
+0.359 dB peak assertion is a sufficient stability guard for a coefficient-only edit.

## 9. BUILD CHECKLIST — THE ORDER THE SCRIPT MUST EXECUTE

The V103 script is the template; keep its `check()` / `SystemExit` discipline and its
`ACCORD_V104_WRITE` gate (default `""` ⇒ **dry run, nothing written**).

1. **LOAD AND PIN THE BASE.** V103 image, assert sha256
   `df6104bdf8e4fcb69f3379f5b85fb591e4c64e4c33c16f6f9bf29cc88f48f71d`, length `0x100000`,
   `walk_all_blocks == 0`. Load stock, assert sha256 `3f1d55a9…fd822`.
2. **ASSERT THE GATE LIST FROM §8 IS CLEARED** — an explicit boolean per hard blocker, `SystemExit`
   if any is unresolved. This is the V103 *"will not write a file until identity is resolved"*
   pattern, generalised.
3. **FROZEN AUDIT, PRE-EDIT.** All 41 cells + the 4 friction records at their V103 values.
   Add `0xC64A3 == 1` to `FROZEN` **as a never-move cell** (§0.2), and `0xC60A8/AC/B0/B4` are
   **removed** from frozen and become edit targets.
4. **PRE-EDIT BYTE VERIFICATION**, read from the base image, not from this spec:
   `0xC6CD0`=5346 · `0xC61B2`=`0xC61B4`=3072 · `0xC674E`=5120 · the four notch quadruples ==
   `f8c2c4bf` / `7576223f` / `0ebef0bf` / `3a3b513f` · hook `0x55C0E`==`86ff26ef` ·
   cave tail virgin `0xFF` from `0xC4B34+164` to `0xC4FF0`.
5. **DERIVE THE NOTCH COEFFICIENTS IN THE SCRIPT** — do not paste the bytes. Compute
   `a1 = −2r cos ω₀`, `a2 = r²`, `b1 = −2 cos ω₀`, `g = (1+a1+a2)/(2+b1)` from `f₀`, `r`, `fs`, pack
   float32 LE, and **assert the packed bytes equal the spec's**. A pasted constant cannot catch a
   typo; a derivation can.
6. **ASSERT THE FILTER'S PROPERTIES FROM THE PACKED BYTES**, before writing them:
   poles `|z| = 0.990000 ± 1e-6` at `7.79 ± 0.001 Hz` · zeros `|z| = 1.000000 ± 1e-6` at the same
   frequency · `|H(0) − 1| < 1e-4` · 🛑 **`max |H|` over a dense 0.1–500 Hz grid ≤ +0.40 dB** ·
   **no interior local maximum further than 0.1 Hz from Nyquist.** Re-run this on **every** cut —
   a denominator-only edit reaches +10.75 dB and this is the assertion that catches it.
7. **IF ITEM A IS IN SCOPE:** compute `clamp = GAIN × 512 // 891`, assert `GAIN % 891 == 0`,
   assert `u16(0xC674E) > clamp`, and **`SystemExit` if not** — this is what caps the build below 10×.
8. **APPLY THE EDITS**, each through an `apply(addr, pre, post)` that asserts `pre` first and records
   every touched byte in an `attributed` set: the four notch cells → (if A) the three gain cells →
   `0x55E10` `sar` → the cave payload.
9. **POST-EDIT READBACK** from the image being built, cell by cell.
10. **LINEAR DECODE OF THE CAVE.** Every byte on an instruction boundary; every `bge +4` target on a
    boundary; **no `ba05`/`b205`** anywhere in the payload; stream ends `movea` + `jmp [lp]`;
    registers ⊆ `{r0, r6, r7, gp, lp}`; stores `(n_b4, n_b7) == (4, 1)`; mask partition disjoint,
    union `{7,6,5,4,3}`, every mask preserves bits 2:0.
11. **GATE 1 RESTATEMENT IN THE SCRIPT** — assert that the three new source cells' own writers
    (`0x358DC`, `0x35A1E`, `0x35AC0`, `0x35ACE`) are **not** in the `attributed` set, and that
    `0xC64FA` is still 5.
12. **FROZEN + friction audit, POST-EDIT.**
13. **ZERO-STRAY CHECK vs the V103 base** — every differing byte inside a named edit or a CRC trailer.
14. **EME AUDIT** — `eme_audit(built, base=V103, stock)` verbatim, including
    `0xC674E > u16(0xC61B2)` and `0xC407E == 511`.
15. **CRC.** Compute owning blocks from the `attributed` set; assert **exactly 2**
    (`0xC4FFC`, `0xC6FFC`); assert no edit sits on a trailer; recompute both; `walk_all_blocks == 0`;
    assert `[0xC5000,0xC5FFC)` byte-identical to the base.
16. **FULL BYTE DIFF vs STOCK** — extend `VS_STOCK` with the four notch ranges (and the gain trio if
    A is in scope); assert **zero unattributed bytes**.
17. **`.rwd` ENCODE + IN-MEMORY READBACK** — decode and assert byte-identical to the built image, CRC
    50/50. **All of this runs in dry-run mode.**
18. **ONLY IF `ACCORD_V104_WRITE` IS SET:** refuse to overwrite a *different* existing image or
    `.rwd`; write; then **re-read both from disk** and re-run FROZEN + friction + EME + the cave
    payload comparison **against the files on disk**, not against script variables.
19. **EXACTLY ONE FLASHABLE `.rwd` PER BUILD NUMBER.** Name the plain image with the build's own
    `TAG` so a re-cut cannot silently overwrite its predecessor (the open V70 hazard,
    `BUILD-LINEAGE.md` Part 2).
20. **WRITE THE DRIVE CARD BEFORE THE FLASH**, carrying §5.4's seven pre-registered sentences
    verbatim, the identity rule, and — if A is in scope — the ×1.70 vibration prediction, stated as a
    prediction.
