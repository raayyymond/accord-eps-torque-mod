## The corrected causal model (this is the load-bearing part)

Full record: `memory/reference_accord_corridor_lockstep.md`. The direction corridor (the soft-EME integrator
reference the command is compared against) is **computed in parallel two ways and cross-checked** — a classic
lockstep-redundancy safety monitor:

| | INTEGER side (cal `0xC674E`/`0xC675A`) | FLOAT twin (cal `0xC6664`) |
|---|---|---|
| dir1 (UPPER) | wall `gp-0x6af6` (0xFEDF150A) | `gp-0x6db0` (0xFEDF1250) |
| dir2 (LOWER) | wall `gp-0x6b00` (0xFEDF1500) | `gp-0x6db8` (0xFEDF1248) |
| integrator / dir1-divergence | `gp-0x6b0a` ACC | `gp-0x6dc0` (0xFEDF1240) |

The **float corridor table** (byte-confirmed): velocity-indexed LERP, f32 `[N][X][Y]` — `N=7 @0xC6644`,
`X=[-7,-6,-5,0,5,6,7] @0xC6648`, `Y=[1.0 ×7] @0xC6664`. **Flat**, so the LERP output = the constant Y. The
integer wall in the monitor's `/1024` units: stock `1024→1.0`, V25/V26 `2048→2.0`.

**Two cross-check sites (same family):**
1. **Inline check A** (`FUN_00042af8`, `0x43172–0x431c0`): `|int(1024.0 × float_twin) − int_wall| ≤ 5`.
   `movhi 0x4480`=1024.0 @0x43176; `trncf.sw` @0x4317e; `sub gp-0x6af6` @0x4318c; `addi 0x5; cmp 0xb`
   @0x4318e/0x43196. Dir2 sibling @0x431a0–0x431b6, **direction-gated** (`mul`/`setfnc` @0x431a4/0x431ac).
2. **`FUN_00043e44`** (float domain): `lp − gp-0x6af6/1024` (`subf.s` @0x4463a) vs threshold
   `0x3ba00000 = 5/1024` (@0x4463e); a bit-weight accumulator (steps `0x3a83126f≈0.001`) crosses `128.0`
   (`movhi 0x4300` @0x44a26) → `jarl 0x462e6` @0x44a4c → **DTC 0xF00049**. Writes the three float twins
   (`gp-0x6db0` @0x449f4, `gp-0x6dc0` @0x44a2a, `gp-0x6db8` @0x44a30); its second LERP block @0x43f88 reads
   the `0xC6648`/`0xC6664` table.

**The arithmetic (dir1 — the instruction-proven case):**

| | float twin `gp-0x6db0` | int wall `gp-0x6af6` | `\|1024·twin − wall\|` | result |
|---|---|---|---|---|
| stock | 1.0 | 1024 | **0** | ✓ pass (V18 never hard-faulted) |
| V25 | 1.0 | 2048 | **1024** | ✗ DTC at full lock |
| V26 | 2.0 | 2048 | **0** | ✓ pass — exact, no rounding |

Full lock trips first because column velocity `gp-0x4f60`≈0 but `gp-0x6acc` (always-on assist demand) drives
the integrator hardest there → the constant desync accumulates to 128.0 fastest.

**Why V26 needs only ONE float edit:** all three checks derive from the same flat magnitude table (`0xC6664`)
× direction sign, and only the **active-direction** check contributes (direction-gated). Doubling `0xC6664`
doubles whichever twin is active to match its doubled wall.

**The "weight-8 proportional window" (V24's killer) IS this corridor lockstep check** (inline check A). V24
broke it from the **envelope** side (`gp-0x3574`, a different quantity → proportional residue); V25 from the
**integer-corridor** side; V26 matches both corridor sides **exactly** (`1024.0×2.0 = 2048` = wall), so the
fixed ±5 tolerance isn't even stressed. The V24 "no fixed-LSB widen can cover" problem does NOT apply here.

## What's ruled out (operator gold data — do not re-attempt)

- **SM2/SM3 threshold raises are NOT the lever.** V19 raised SM2 (`0xC6422`) → soft EME still triggered.
  V20 raised SM3 (`0xC61DC`) further → HARD EMEs, EPS out, restart required. The soft EME is the integrator
  accumulation itself, not a threshold event → the fix must PREVENT accumulation (widen the corridor).
- **The corridor is not a clean unmonitored lever** (V25 CLEAN's claim). It's lockstep-monitored; any change
  to the integer corridor must be matched on the float side, or the monitor DTCs.
