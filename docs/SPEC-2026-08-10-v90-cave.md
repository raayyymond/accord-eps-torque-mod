**Author:** `CaveSpec`. **Rev 3, 2026-08-10 — PROBE-ONLY scope.** Supersedes rev 2 entirely.
**Status: SPEC ONLY — nothing built, no build script touched.**

## 🛑 0. DEFECT IN REV 2 — READ THIS FIRST IF YOU HAVE REV 2's PAYLOAD

**Rev 2's payload hex string was BYTE-SWAPPED on every 2-byte instruction.** I generated it with
`bytes.fromhex("3a00")` — which emits `3a 00` — where V850 little-endian needs `00 3a`. The 4-byte
entries were copied from byte dumps and were correct; the 2-byte ones were typed as halfword *values*
and were not. Rev 1 used a proper LE encoder and was right; rev 2 regressed.

**Do not use any payload string from rev 2.** If a builder has it, the cave would decode as garbage.
Caught by the branch-target self-check in this rev going silent: with the bytes reversed, `ae05` reads as
`05ae`, whose opcode field is `0xC` not `0xB`, so no instruction matched the branch filter. **A check
that produces no output is not a check that passed** — that is the lesson, and it is why the validator
in §7 now asserts a boolean rather than printing.

Rev 3's payload below is generated by an explicit `LE(hwval)` encoder and every branch target is
asserted to land on an instruction boundary.

## 1. Scope: PROBE-ONLY. No calibration edit.

**V90 = flown V89 + a re-specced cave + the 2-byte CAN 427 repoint. Nothing else.** The `0xCBE74` dose is
dropped (the lever's only two flights, V74 and V75, both hard-faulted with a latched ECU, and it could
not be sized).

**Three consequences that make the design simpler and more honest:**
- No dose ⇒ **no dose-in-force question** ⇒ no rung threshold has to straddle an undosed/dosed pair.
- The flatten-vs-uniform hazard I raised in rev 1 is **void** — nothing is scaled, so no rung can read
  dead-because-out-of-regime.
- ⊕ **The one shaky input in rev 2 stops mattering.** `gp-0x6b26`'s 73–109 ct sizing is *inherited, not
  measured* (it came from the chain that was struck). Rev 2 leaned on it for three threshold rungs.
  **Rev 3's only `gp-0x6b26` rung is SIGN, whose duty is ~0.50 by construction at any amplitude.** The
  magnitude question moves to 427, which measures it instead of assuming it.
- `0xC40D2` stays at 204, so V89's friction lever remains on the car and stays observed (b5).

### 🛑 Correction to carry forward: an address is not a mode, and the Y row is at record base + 8

Byte-verified map. Recorded here because a future builder will read this document:

```
mode 24 (MANUAL,  this car)   record 0xD6A64   X 0xD6A66   Y 0xD6A6C    never dosed, ever
mode 26 (ENGAGED, this car)   record 0xD7A54   X 0xD7A56   Y 0xD7A5C    dosed x1.5 on V74/V75
```
`0xD6A5C` is **mode 23**, not mode 24 — that was V74's *dosed* set, not this car's *target* set.
**Rule: dereference `0xCBE74 + mode*4` and print the mode number beside the address.**

🛑 **Writing Y values at the record base is not merely "the wrong array" — it is silently plausible.**
They land in the **X breakpoint array**, which the LERP compares **UNSIGNED**: `−29490` reads as
`36046`, every speed falls below `X[0]`, and the table returns a **flat `Y[0]` at all speeds** — a
**5× increase at highway** that looks like a working calibration. (Credit: `DampAxis` raised the `+8`
offset; my own `read_memory 0xD7A54,16` = `0300 0000 0005 8016 9ad9 9ae9 52f8 0000` corroborates it —
`n=3` at +0, X at +2, Y at +8.) **V90 touches none of this.**

## 2. The rung table

| bit | signal | test | cell census | predicted duty |
|---|---|---|---|---|
| **b7** `0x80` | `gp-0x6b26` **SIGN** | `cmp 0 ; bge` ⇒ `x < 0` signed | 1W / 4R | **~0.50 by construction** |
| **b6** `0x40` | `\|gp-0x6bf6\| ≥ 512` — **\|MODEL\|** | `subr ; sar 9 ; cmp 0 ; bnh` | **2W / 0R** | 0.10 – 0.50 **[B]** |
| **b5** `0x20` | `gp-0x6ae2 ≠ 0` — **FRICTION relay active** | `cmp 0 ; bnh` unsigned | **1W / 0R** | **0.49 – 0.54 [E]** |
| **b4** `0x10` | `gp-0x6c00 < 0` — **OBSERVER GATE FAILED** | `cmp 0 ; bge` | **1W / 0R** | ~0.000 (one-shot question) |
| **b3** `0x08` | **FINGERPRINT** | unconditional | — | 1.000 |

Plus **CAN 427 (`0x1AB`) `MOTOR_TORQUE` = `clamp(\|gp-0x6b26\|·5>>3, 0, 0x3FF)` at 50 Hz** — ~9 effective
bits, never clipping.

### Why this allocation

Following your priority order (gate > `|model|`/friction separation > coarse magnitude cross-check >
fingerprint), with two deviations I own:

- **b7 SIGN is effectively mandatory, not optional.** 427 delivers `|gp-0x6b26|` at **50 Hz ⇒ Nyquist
  24.9 Hz**, so **427 cannot see the 18–28 Hz band at all**, and it is rectified, which doubles apparent
  frequency and destroys phase. The 100 Hz sign bit is the **only** channel in the build that reaches
  that band, and with 427 it reconstructs the signed value — V88's proven design on the new cell.
- **b3 FINGERPRINT retained** despite being last in your order, on `FlightV89`'s explicit measurement:
  V89's all-zero payload is 59.5 %/50.8 % of frames, and without b3 those are indistinguishable from a
  cave that never fired. On a **probe-only** build, whose entire deliverable is instrument quality,
  shipping an instrument with no per-frame liveness proof is the wrong trade. It is also no longer
  needed for identity (§4 gets that free), so it is bought purely as liveness.

**Dropped: the coarse magnitude cross-check on `gp-0x6b26`.** Your ranking put it below the
`|model|`/friction pair and I agree. **What it costs, stated plainly:**
1. **The frame-exact 427↔cave identity check is downgraded to a statistical one.** With no cave bit
   reading `|gp-0x6b26|`, nothing cross-validates 427 frame-by-frame. What remains: sign flips in b7
   must coincide with 427 dipping toward 0 (`427 == 0 ⟺ |x| ≤ 1`). Real, but a correlation, not an
   identity. **Identity itself does not depend on this** — §4 is single-frame and decisive.
2. **No structural nesting invariant.** Four independent signals means no `b_hi ⊂ b_lo` self-check that
   the rung map is being read correctly. The surviving map validator is weaker: **b3 ≡ 1, so every
   observed field value must be ODD.** Any even value ⇒ the cave did not run or the map is wrong.
3. No 100 Hz *magnitude* for `gp-0x6b26` above 427's 25 Hz Nyquist — only the 1-bit sign. Precedent
   says that is enough: V87/V88 used exactly a 100 Hz sign bit and got coherence 0.439 vs shuffled 0.178.

## 3. Sizing

**b5 `gp-0x6ae2 ≠ 0` — [E], and it is the best-placed bit in the build.** `FlightV89` measured V89's
identical rung at **0.536 / 0.495 engaged**, with strong rate dependence (0.16 at <0.35 °/s → 0.99 above
25 °/s). Near-optimal information for a single bit, and because it is **V89's own rung unchanged**, the
V89↔V90 friction comparison is apples-to-apples. (V89's `≥64` rung was badly placed at 0.037/0.069 —
that is why I take NONZERO, not a magnitude threshold.)

**b6 `|gp-0x6bf6| ≥ 512` — [B], and it is the ONE guessed parameter in this design. Say so out loud.**
Derived from the observer's own arithmetic, with `K0 = 0` and ignoring the EMA:

```python
# gp-0x6ae2 = 1024 * friction ;  friction ~ |model| * relay * K1/1024 ;  gp-0x6bf6 = 2639 * model
# =>  gp_6ae2  ~  K1 * |gp_6bf6| / 2639 * relay  =  0.0773 * |gp_6bf6| * relay     (K1 = 204)
# relay = clamp(polarity * gp_6abc / 50, +-1)  ->  saturates at +-1 above 50 ct = 10.6 deg/s
```
Inverting `FlightV89`'s two measured V89 duties: `P(gp-0x6ae2 ≥ 64) ≈ 0.05` ⇒ `P(|6bf6|·relay ≥ 828) ≈
0.05`; `P(gp-0x6ae2 ≠ 0) ≈ 0.50` ⇒ `P(|6bf6|·relay ≥ 12.9) ≈ 0.50`. Since `|relay| ≤ 1`, `|6bf6|` is at
least these values, so `duty(|6bf6| ≥ 512)` sits somewhere in **0.10 – 0.50**. Wide, and honestly so.

⊕ **Mitigation, and it is why this is safe to ship guessed:** the threshold is **one byte** at
**`0xC4B4A` (`0xA0 | shift`)**, and the joint `(b6, b5)` table says which way to move it. Thresholds
available from that single byte: `sar 8` → 256, `sar 9` → **512**, `sar 10` → 1024, `sar 11` → 2048.

**What the (b6, b5) pair buys — the separation you asked for.** Since `gp-0x6ae2 ≈ 0.0773·|gp-0x6bf6|·relay`,
frames with **b6 = 1 and b5 = 0** are *large model, zero friction* ⇒ **`relay ≈ 0`**, i.e. polarity zero
or a rate crossing — not a small model. That is exactly the `|model|`-vs-`ratio` confound, read directly
off a 2×2 contingency table.

⚠ **Honest limit: two threshold bits give the joint DISTRIBUTION, not the per-frame ratio.**
`ratio = (gp-0x6ae2/1024)/(|gp-0x6bf6|/2639)×(1024/K1)` needs both *values*. V90 delivers a 2×2 table
conditioned on wheel rate, which is a real advance over V89's single conflated bit but is not the
per-frame number. **If the friction lane is ever reopened for a dose, 427 should carry `gp-0x6bf6` on
that build** — then `|model|` arrives at 9 bits and one cave bit on friction gives the ratio properly.

**b4 gate — one-shot question, and I accept the trade you named.** Duty ~0.000 expected. For a gate
question 0.000 *is* the answer, and if it ever fires it invalidates a class of inference. **Score it
engaged/manual and by wheel rate, not as a route average.**

🛑 **The failure mode b4 does NOT catch, and it is the bigger one.** At `(char)gp-0x6752 == 0` the
command branch itself zeroes (`gp-0x6b98 × cVar5`), so **model, friction and inertia collapse together
while the observer emits a valid non-sentinel output** — and polarity 0 **PASSES** the gate
(`0 + 1 = 1 < 3`), so all four sentinels read *success*. **b6 = 0 ∧ b5 = 0 is the signature**, but it is
degenerate with "genuinely small". A future friction probe should carry `gp-0x6752` itself.

## 4. Identity — single-frame, and V89's support is now a strict SUBSET of V90's

`FlightV89` established that V86B/V87/V88/V89 all emit exactly `{3, 7, 15, 23, 31}` — support cannot
separate them — because on all four `b4 ≡ 1.0000` (254,085 frames) and the payload bits obey `b6 ⇒ b5`
and `b7 ⇒ b5` (all three read one cell). **V90 puts four INDEPENDENT signals on b7/b6/b5/b4**, so every
implication breaks and all 16 odd codewords become reachable:

| | reachable `(byte4 >> 3) & 0x1F` |
|---|---|
| **V86B / V87 / V88 / V89** (measured) | `3, 7, 15, 23, 31` |
| **V90** (enumerated) | all 16 odd values `1 … 31` |
| **V90-ONLY** | `1, 5, 9, 11, 13, 17, 19, 21, 25, 27, 29` |

```
   ANY frame with b4 == 0   ->   V90.
   Values 1, 5, 9, 13, 17, 21, 25, 29 are ALL b4 == 0.
```
**`b4 == 0` is impossible on V86B/V87/V88/V89 across 254,085 measured frames, and is the ~100 % case on
V90** (the observer gate is expected never to fail). So **essentially every V90 frame is discriminating** —
one frame, parameter-free, no thresholds, no duties, no control route, no reference cache.

This includes the values `11` and `19` that `FlightV89` independently named as the target. Their route
required three independent quantities; this allocation has four, so the whole odd alphabet opens.

⚠ **One-sided, and worth stating:** observing only `{3,7,15,23,31}` would be consistent with either
build. It is not: those five all require `b4 = 1`, i.e. a *failing* observer gate on every frame.
**Map validator:** `b3 ≡ 1` ⇒ **every observed value must be odd.** An even value means the cave did not
run or the field is being read at the wrong bit offset.

## 5. CAN 427 repoint — accepted, and it is the primary instrument

**[E]** `decompile_function 0x55d80`: the CAN **`0x1AB` = 427** builder ends
`FUN_00057b24(gp-0x13cc, 3, 0x1ab)`, and its `MOTOR_TORQUE` field is
`FUN_00049a90((int)((|x| & 0xffff) * 5) >> 3, 0, 0x3ff)` with `FUN_00049a5a` = `abs()`.

```
    0x55DF2 :  68 94   ->   da 94
```
Stock is `2437 e893` (`gp-0x6c18`); V87 repointed it to `2437 6894` (`gp-0x6b98`) and V88/V89 inherited
that — **verified on the V89 image**. The new hw2 `da94` is the **same halfword as the cave's own
`ld.h -0x6b26[gp]`**, so one twin covers both.

- `|gp-0x6b26| ≤ 511` (clamp `0xC407E`, verified = `ff01` = 511 on the V89 image) ⇒ `511·5>>3 = 319`
  in a 10-bit field ⇒ **never clips**; 1.6 ct/LSB, ~9 effective bits at 50 Hz.
- **Delivers the `gp-0x6b26` baseline that exists on no build** — the flight's whole point under
  probe-only, and what would let a future dose be sized rather than guessed.
- **[E] Same CRC block as the cave — see §5.1, which settles a disagreement.** `0xC4FFC` is the **ONLY**
  CRC word this build needs.
- Cost: 427 stops carrying `gp-0x6b98`. Acknowledged.

### 5.1 🛑 CRC: exactly ONE trailer, `0xC4FFC`. Do NOT emit one at `0x055FFC`.

A second trailer at `0x055FFC` was proposed on the reasoning that CRC blocks are uniform 4 KB pages, so
`0x55DF2` would live in a `0x055000` block. **They are not uniform pages — they are a self-describing
linked list**, and this kit's own verifier says so. Replaying
`verify_bootloader_crc.py::_blocks` on the flown V89 image:

```
0x55C0E  hook             -> block [0x013000,0x0C4FFC)   TRAILER 0x0C4FFC
0x55DF2  427 packer disp  -> block [0x013000,0x0C4FFC)   TRAILER 0x0C4FFC
0xC40D2  K1               -> block [0x013000,0x0C4FFC)   TRAILER 0x0C4FFC
0xC4B34..0xC4B7D  cave    -> block [0x013000,0x0C4FFC)   TRAILER 0x0C4FFC
```
**One block, 0xB1FFC bytes, covers all of it** — that is the bootloader's own hard-coded main block
(`0xB07A/0xB080`: `0x13000` and `0xB1FFC`). Verified end to end on the V89 image:
`zlib.crc32(img[0x13000 : 0x13000+0xB1FFC]) = df43b558`, and `img[0xC4FFC:0xC5000] = 58b543df` ⇒
**MATCH**.

🛑 **Emitting a trailer at `0x055FFC` would BRICK the ECU, twice over:**
1. `0x055FFC` is **inside** `[0x013000, 0x0C4FFC)`, so writing there **invalidates the real `0xC4FFC`
   CRC** it is supposed to help.
2. **`0x055FFC` is live code.** `img[0x55FFC:0x56000] = 6477b8f0`, and Ghidra reads it as
   **`st.h r14, -0xf48, gp` inside `FUN_00055f2e`**. Four bytes of "CRC" would overwrite a store.

⊕ **Cheap general test for whether an address is a trailer:** a real trailer has sane link fields at
`-8`/`-6`. `0xC4FFC` → `start_page=0x0000, num_pages=0x00C6` ✓; `0xD7FFC` → `0x0000 / 0x00D9` ✓;
**`0x055FFC` → `start_page=0x5EC8` = block start `0x5EC8000` = 99 MB, past the end of a 1 MB image** ✗.
Garbage, because they are not link fields — they are instructions.

## 6. GATE 1 — RAM ownership

| cell | access | census (both tools, set-differenced) |
|---|---|---|
| `gp-0x6b26` | **read** | 1W (`0x36CF0`) / 4R |
| `gp-0x6bf6` | **read** | **2W** (`0x3BAC0` success, `0x3BC0E` fail) / **0R** |
| `gp-0x6ae2` | **read** | **1W** (`0x3BC04`) / **0R** |
| `gp-0x6c00` | **read** | **1W** (`0x3BC16`) / **0R** |
| `gp-0x1514` | **read-modify-write, bits 7:3 only** | the only cell written |
| `gp-0x1518` | not accessed — `movea` immediate only | — |

**All four new cells are READ-only from the cave ⇒ zero blast radius; a load has no side effects.** Three
of the four are pure write-only diagnostic taps (0 firmware readers), the best available class.
**No new RAM claimed.** Leaf: no `prepare`, no stack, no call, no persistent state; scratch is **r6 and
r7 only** — the 50-build invariant.

⚠ Correction to a figure in circulation: `gp-0x6bf6` is **2 writers**, not 1 — one store per arm
(`0x3BAC0` success, `0x3BC0E` fail). That **strengthens** the point that it is never stale, unlike
`gp-0x6ae0`/`gp-0x6ae2` which are success-path-only.

### 6.1 Method, and what each tool missed

Python over `[0x13000, 0xC5000)`: **(A)** 4-byte Format VII gp-relative (opcode `0x38–0x3F`, handling
`hw2 = disp|1` and `ld.bu`'s disp bit 0 in hw1 bit 5); **(B)** 6-byte extended-displacement, 0-indexed
decoder; **(C)** register-indirect `movhi 0xFEDF,r0,rN` + memory/bit-op on `rN`, opcode-filtered with a
96-byte locality window. Ghidra `search_instructions` as the independent second method. Form **B** was
empty on every cell.

🛑 **The census rule paid for itself on the write target.** Ghidra reports 8 accesses to `gp-0x1514` and
**misses two live writers**:
```
00055b1c: movhi -0x121,r0,r18     ; 0xFEDF
00055b20: clr1  0x1,0x6aec[r18]   ; = gp-0x1514, bit 1
00055b2c: movhi -0x121,r0,r18
00055b30: clr1  0x0,0x6aec[r18]   ; = gp-0x1514, bit 0
```
Their operand text is `0x6aec, r18` — **the string `1514` never appears**, so no operand-pattern search
can find them. (My first, unfiltered C-form pass gave 11 and 31 raw hits; the surplus were halfword
coincidences in the LERP/cal data region with no `movhi` in range, removed by the opcode + locality
filter.) Text-match FPs adjudicated out: `0x1512A`, `0x15C48`, `0x6B25A`, `0x6B25E`, `0x26BF4`,
`0x26BF8`, `0x6BF60`, `0x46A86`, `0x46A8E`, `0x6AEC2`; and `0x5DFFA`/`0x5F5B0` are `movea 0x6c00,r0,r7`
— an immediate against **r0**, not `gp`.

### 6.2 Bits 7:3 are free — every writer accounted for

`0x55AC0` / `0x55AE8` / `0x55B06` are `st.b` after `andi 0xfb` / `0xfd` / `0xfe` (bits 2/1/0 only);
`0x55B20` / `0x55B30` are `clr1` on bits 1/0; `0x2194A` is a read. The one needing care is
`FUN_0002193e`, a **32-bit** RMW straddling our byte:
`*(uint*)(gp-0x1514) = *(uint*)(gp-0x1514) & 0xff0000ff | (byteswap16(arg) << 8)` — little-endian, the
word spans `gp-0x1514 … gp-0x1511`, mask bits 7:0 map to `gp-0x1514` and are `0xff` ⇒ **byte 4 preserved
in full**; it writes bytes 5 and 6, at `0x55B44`, before our hook.
⇒ **No Honda code sets or clears bits 7:3 of `gp-0x1514`.** **[E]**, three encodings, two tools.

### 6.3 ★ The hook already sits inside Honda's own critical section

```
00055c0a: jarl 0x0001fa42,lp    ; FUN_0001fa42: nesting counter @gp-0x163c + `di`
00055c0e: movea -0x1518,gp,r6   ; <-- HOOK
00055c18: jarl 0x00057b24,lp    ; FUN_00057b24(buf=gp-0x1518, len=8, id=0x14A)
00055c2e: jarl 0x0001fa72,lp    ; FUN_0001fa72: decrement + `ei`
```
Both disassembled **[E]**. The cave's RMW is not wrapped in the pair itself — and structurally cannot be,
since a `jarl` would destroy the `lp` it returns through — **but it executes inside Honda's bracket.**
🛑 Property of *this* site; does not transfer to a new one. It also means the cave lengthens that
critical section, so interrupt latency is the cost metric (§8). The same call proves the byte map from
the call site rather than a table: base `gp-0x1518`, length 8 ⇒ **`gp-0x1514` is `0x14A` byte 4**.

### 6.4 Register ownership **[E]**

`lp` dead (written by `jarl` at `0x55C0A`, again at `0x55C18`, never read between) · `r6` dead (the
hooked instruction's own destination, restored by the byte-copy) · `r7` dead (unconditionally
overwritten by `mov 0x8,r7` at `0x55C12`) · `r8`, `r10`–`r18`, `r28`, `sp`, `ep` never touched.

### 6.5 🛑 What this does NOT cover

Static clearance is **not sufficient** — **`gp-0x1500` passed both static methods and still failed
on-car in V48B**, aliasing a live monitor/DTC byte, and the motor slammed to the clamp. Not covered: a
monitor reading the *transmitted* `0x14A` back and cross-checking reserved bits; DMA or peripheral
aliasing at `0xFEDF6AEC`; another ECU or the gateway validating byte 4's spare bits; any writer in a
region Ghidra has not analysed whose encoding the three scan forms miss.

**The load-bearing evidence is empirical: these exact bits have been written by ~50 flown builds with no
fault, no DTC and no drivability report.** V90 changes *what is computed*, not *where it is stored*.

### Python mirror (for the decoder — mirrors the integer arithmetic exactly)

```python
M32 = 0xFFFFFFFF
def wire_byte4(x6b26, x6bf6, x6ae2, x6c00, honda_bits=0x7):
    r7 = 0
    r6 = x6b26                                   # 0xC4B36 ld.h (SIGN-EXTENDS)
    if not r6 >= 0:         r7 += 8              # 0xC4B3A cmp / 0xC4B3C bge   b7 SIGN
    r6 = x6bf6                                   # 0xC4B40 ld.h
    if not r6 >= 0: r6 = 0 - r6                  # 0xC4B44 cmp / 46 bge / 48 subr   r6 = |x|
    r6 = r6 >> 9                                 # 0xC4B4A sar 0x9
    if not (r6 & M32) <= 0: r7 += 4              # 0xC4B4C cmp / 0xC4B4E bnh   b6 |model|>=512
    r6 = x6ae2                                   # 0xC4B52 ld.h
    if not (r6 & M32) <= 0: r7 += 2              # 0xC4B56 cmp / 0xC4B58 bnh   b5 friction != 0
    r6 = x6c00                                   # 0xC4B5C ld.h
    if not r6 >= 0:         r7 += 1              # 0xC4B60 cmp / 0xC4B62 bge   b4 GATE FAILED
    return ((honda_bits & 0x7) | (((r7 << 4) & M32) + 8)) & 0xFF   # 0xC4B66 shl / 0xC4B68 add
```

## 8. Cycle cost

**29 instructions, straight-line, once per `0x14A` transmission = 100 Hz.** 🛑 **No loop, no divide, no
call, no floating point** ⇒ the re-check required of any cave introducing one does not apply. Worst path
= 29; the five branches skip 2-byte instructions, not work. **+4 over V89's 25.**

At a conservative 40 MHz and ~1.5 cyc/instr: **~1.1 µs per 10 ms frame ≈ 0.011 % duty**; the added
critical-section length at `0x55C0A…0x55C2E` is ~0.15 µs over V89. **[E]** for the instruction count
(assembled and listed); **[B]** for the clock, which is a bound.

DTC 0x18 is a **boot-only reset-cause report, not a live deadline monitor** ⇒ no per-task timing budget.

## 9. CAN side

- **`0x14A` byte 4 bits 7:3** are the free bits — **not** `0x18F`. §6.2 shows Honda never touches them.
- Gateway is a **whitelist** (`0x14A` / `0x18F` / `0x1AB` only); V90 introduces no new ID and the
  repointed 427 **is** `0x1AB`, already on the whitelist.
- **Checksum** computed inside `FUN_00057b24`, called at `0x55C18` — **after** the cave's write ⇒ spare
  bits auto-covered. **[E]** from the call ordering.
- ⚠ **FOURFRAME `STRB`/`SSAM` cannot recur.** That defect was *our* bug in a cave that **originated a
  frame** and set the message-control bits itself (`STRB = 0x80`, `SSAM = 0`). This cave touches **no CAN
  peripheral register** — it edits one RAM byte in a buffer Honda's own unmodified code transmits.
- 🛑 **`raw14` off-by-one is a CACHE defect — do not fix it in firmware.** Pair `(raw14_t, raw14_b4)` or
  `(t, probe)`, never crossed; crossing reads the byte ~10 ms early = 28° at 7.79 Hz.
- ⚠ **The `0x18F`-vs-`0x14A` staleness question is UNRESOLVED.** **No part of this spec rests on either
  version** — the cave writes `0x14A` and every rung is a same-frame instantaneous test. **427 (`0x1AB`)
  is a different frame and its 50 Hz cadence relative to `0x14A`'s 100 Hz DOES matter** for the
  signed-reconstruction analysis: pair 427 to the cave stream by timestamp, and do not assume alignment.
