## TL;DR

- **V27 was flashed and HARD-FAULTED immediately the moment the wheel was turned** — wheel un-turnable.
  Same *class* of failure as V26 (a near-t=0 divergence), different quantity.
- **Root cause of the V27 failure (decomp + 4 tracers + algebra + the real table bytes):** V27 doubles
  BOTH the float corridor **twin** (`gp-0x6db0/db8`, via the `0xC4E00` trampoline) AND the integer
  **wall** (`gp-0x6af6/b00`, via cal `0xC674E`). Both reach **exactly 2×**, and the primary corridor
  tables match exactly — so by steady-state math V27 *should* pass. But the watchdog twin is
  `polarity × max(corridor, SECONDARY tables)` (table `0xC65B8`, Y up to **2.0**). In stock the
  secondary term exceeds the corridor by a small **residual ≤ 5/1024** (inside the monitor window).
  Doubling both twin and wall **doubles that residual**:
  `divergence_V27 = 2 × (stock divergence) ≤ 2×5/1024 = 10/1024`, which busts the ±5/1024 (Monitor 2)
  / ±5 LSB (Monitor 1) window the instant **polarity ≠ 0** (any steering) → fault SM → `0x3f1b` hard
  shutdown in ~10 cycles. **No symmetric doubling can avoid it — the residual itself doubles.**
- **V28 = `builds/v18_v49/build_v28_tva.py`** = V27 + a **proportional 2× widen of BOTH corridor consistency
  monitors** so the doubled residual fits. Built + self-checked. **49/49 CRC PASS.**

## The corrected causal model (load-bearing)

Full record: `memory/reference/firmware/reference_accord_corridor_lockstep.md`. The corridor is computed in both domains and
cross-checked by **two** monitors (Monitor 1 in the shaper `FUN_00042af8`, Monitor 2 in the watchdog
`FUN_00043e44`). Each monitor's corridor check is `| twin − wall/1024 | ≤ tolerance`.

| | INTEGER wall (cal `0xC674E`/`0xC675A` → shaper LERP) | FLOAT twin (`FUN_00043e44`) |
|---|---|---|
| dir1 | `gp-0x6af6` (= `corridor_LERP × polarity`) | `gp-0x6db0` = `polarity × max(corridor, secondary)` |
| dir2 | `gp-0x6b00` | `gp-0x6db8` |

- The **wall** = `corridor × polarity`, single table, instantaneous (cal `0xC674E` is read once @0x43066
  in the shaper → `gp-0x6af6`; **doubling the cal cleanly doubles the wall**). It ALSO feeds the
  soft-EME integrator `gp-0x3570`, so the cal-widen is what addresses the soft EME.
- The **twin** = `polarity × max(corridor_mirror, secondary)`. The corridor mirror (`0xC6590`/`0xC65A4`)
  is an exact float mirror of the int corridor (residual 0). The **secondary** tables (`0xC65B8` etc.,
  Y up to 2.0) can make the twin slightly exceed the corridor → the **residual**.
- **Why both ×2 still fault:** `divergence = polarity × max(0, secondary − corridor)`; V27 doubles twin
  and wall, so `divergence_V27 = 2 × divergence_stock`. Stock ≤ 5/1024 (the car works stock) → V27 ≤
  10/1024 — over the ±5/1024 window.

### The V24/V25/V26/V27/V28 ladder

| Build | int wall | float twin | monitor tol | result |
|---|---|---|---|---|
| **V24** | stock | doubled (cave) | stock | float 2× vs int 1× → fault |
| **V25** | ×2 (cal) | stock | stock | int 2× vs float 1× → fault at full lock |
| **V26** | ×2 (cal) | stock — but `0xC6664` doubled (**wrong table**) | stock | envelope +2.0 offset → fault AT REST |
| **V27** | ×2 (cal) | ×2 (trampoline) | stock | both 2× → **2× residual** > ±5/1024 → fault when turning |
| **V28** | ×2 (cal) | ×2 (trampoline) | **×2 (10/1024 / ±15 LSB)** | 2× residual ≤ 10/1024 → fits ✓ |

V28 is the first build where the monitor tolerance is matched to the 2× corridor design point. The 2×
widen is **provably sufficient** for the corridor checks: stock ≤ 5/1024 everywhere ⇒ V27 ≤ 10/1024
everywhere ⇒ a 10/1024 window always passes; a genuinely-wrong corridor (~1.0 = 1024 LSB) is still
caught — recalibration, not blinding.

## V28 exact edit set (`builds/v18_v49/build_v28_tva.py`)

**Everything from V27 (byte-identical):**
- Cal (block #48): GAIN `0xC646C` 891→1782 ; CLAMP `0xC61B4`/`0xC61B2` 512→1024 ; RAMP `0xC64DE` 0x11→0x1B ;
  INT corridor dir1 Y `0xC674E`/`0xC6750` +1024→+2048, dir2 Y `0xC675A`/`0xC675C` −1024→−2048.
- Code (main): trampoline `0x4463A subf.s r2,lp,r10 → jr 0xC4E00`; cave `0xC4E00..0xC4E0F`
  (`addf.s lp,lp,lp` / `addf.s r20,r20,r20` / `subf.s r2,lp,r10` / `jr 0x4463e`).
- PN `0x13109`/`0x14120` `'-'→','`. `0xC6664` LEFT STOCK.

**NEW in V28 — 10 tolerance bytes (main block, byte-scan verified on stock `code.bin`):**

*Monitor 2 (watchdog `FUN_00043e44`) — `movhi` immediates `±5/1024 → ±10/1024`:*
- `0x44640`/`0x44641` `a0 3b → 20 3c` : `r7` `movhi 0x3ba0→0x3c20` (= +10/1024). **Shared positive** —
  used by dir1, dir2, and weights 4/16/32; widening it is harmless for the trackers.
- `0x44648`/`0x44649` `a0 bb → 20 bc` : `r14` `movhi 0xbba0→0xbc20` (= −10/1024) — **dir1 negative**.
- `0x4466C`/`0x4466D` `a0 bb → 20 bc` : `r16` `movhi 0xbba0→0xbc20` (= −10/1024) — **dir2 negative**.
- ⚠ The two **non-corridor** negatives (`0x4478C` r8, `0x448E6` r8) were **LEFT STOCK** (they belong to
  weights that track; the build asserts they stay `0xbba0`). The negatives are *separate* `movhi`
  constants per check — a positive-only widen would have bricked asymmetrically. (`search_instructions`
  missed the `0xbba0` movhi at `0x44646`; a raw **byte scan** found them all — see method note.)

*Monitor 1 (shaper `FUN_00042af8`) — one signed-via-unsigned-wrap window per direction, `±5 → ~±15` LSB:*
- dir1: `0x43190 addi 0x5→0xf` ; `0x43196 cmp 0xb→0x1e` (`6b→7e`, → `0x7a7e`).
- dir2: `0x431B4 addi 0x5→0xf` ; `0x431B6 cmp 0xb→0x1e` (`6b→7e`, → `0x327e`).
- `±15` (not exactly `±10`) gives margin for the `±1` `trunc()` rounding in `trunc(twin×1024) − wall`.

Only the **dir1/dir2 corridor** checks are widened. The integrator (weight 4) and delivered-torque
(weight 32) checks **track** (their twins are NOT doubled by the trampoline; both sides see the same
widened wall) and are left at their own (stock) tolerances.

CRC: block #48 `@0xC6FFC`, main `@0xC4FFC`.
