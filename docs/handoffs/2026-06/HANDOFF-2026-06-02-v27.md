## TL;DR

- **V26 was flashed and HARD-FAULTED immediately on startup — the wheel could not be turned at all.**
  Worse than V25 (which drove ~5–10 ft and faulted only at full lock). This falsified the V26 premise.
- **Root cause of the V26 failure (instruction-verified on STOCK `code.bin`):** cal `0xC6664` is **LERP_B**,
  a velocity *envelope* multiplier — **NOT** the float corridor twin. The float watchdog envelope is
  `base/1024 + lerp_b·lerp_a`, and **at rest `lerp_a = 2.0`**. So doubling `0xC6664` (1.0→2.0) added a
  constant **+2.0 envelope offset at every operating point including parked/centered** → the watchdog
  diverged from the (un-widened) integer side from t=0 → DTC `0xF00049` + latched motor-off in ~10 cycles.
- **The REAL float corridor twins** are RAM `lp` (dir1 → `gp-0x6db0`) and `r20` (dir2 → `gp-0x6db8`),
  computed in `FUN_00043e44` as `corridor_mag × float(polarity gp-0x6752)`. **V27 doubles them via a code
  trampoline** so both lockstep monitors track the widened corridor and stay live.
- **V27 = `builds/v18_v49/build_v27_tva.py`**, built + self-checked + Ghidra-verified on the built image.
  `../accord-firmware/flashing-2020accord/rwd/39990-TVA,A160-V27-LKAS-2x-corridor2x-twindbl-codetrampoline-PNfix-0x13000-0x100000.rwd`.
  **STUDY ARTIFACT — no flash until the operator names file + bus.**

## The corrected causal model (load-bearing)

Full record: `memory/reference/firmware/reference_accord_corridor_lockstep.md`. The direction corridor is computed in both
domains and cross-checked by **two** monitors; widening the integer corridor faults DTC `0xF00049` unless
the **float corridor twins** are matched.

| | INTEGER side (cal `0xC674E`/`0xC675A` → LERP) | FLOAT twin (computed in `FUN_00043e44`) |
|---|---|---|
| dir1 (UPPER) | wall `gp-0x6af6` (0xFEDF150A) | `lp` → `gp-0x6db0` (0xFEDF1250) @0x449f4 |
| dir2 (LOWER) | wall `gp-0x6b00` (0xFEDF1500) | `r20` → `gp-0x6db8` (0xFEDF1248) @0x44a30 |

- **Float twin computation [V]:** `r13 = float(polarity gp-0x6752)` (±1); `lp = r2_corridor × r13`
  (@0x4461e dir1 / @0x44624 dir2); `r20 = r13 × r9_corridor` (@0x4462e). `gp-0x6dc0` (integrator twin,
  @0x44a2a from r10) is a SEPARATE quantity — unaffected by lp/r20.
- **Monitor 1** = `FUN_00042af8` @`0x43172`: `trunc(gp-0x6db0 × 1024) − gp-0x6af6`, tolerance ~±15.
  (Scale const `1024.0` @0x43176 is shared with dir2 @0x43192 and the integrator check @0x4328c.)
- **Monitor 2** = `FUN_00043e44` @`0x4463a`/`0x44662`: `|twin − float(wall)/1024| ≤ 5/1024 (0x3ba00000)`
  → weights 1.0 (dir1) / 2.0 (dir2) → fault_word ≥128.0 @0x44a2e → `FUN_000462e6(0x3f1b)` → the latched
  hard-shutdown chain. Its fault-SM enable gate `0xC64A4` = `0` = ENABLED (verified; **not** `0xC74A4`).
- **Why full lock, not rest:** the int wall and float corridor magnitude are command/angle LERPs — ≈0 near
  center, maxing at full lock. So at rest twin≈wall≈0 (no divergence); at full lock the widened wall/1024
  = ±2.0 while the stock twin = ±1.0 → divergence ±1.0 ≫ 5/1024 → fault. (Matches V25's behavior exactly.)

### The V24/V25/V26/V27 ladder — each had only part of the fix

| Build | int corridor (`0xC674E`) | float twin (lp/r20) | result |
|---|---|---|---|
| **V24** | ±1024 (stock) | **doubled** (cave trampoline) | float 2.0 vs int 1.0 → fault (float-only) |
| **V25** | **±2048** | stock 1.0 | int 2.0 vs float 1.0 → fault at full lock (int-only) |
| **V26** | ±2048 | stock — but `0xC6664` doubled (**wrong table**) | envelope +2.0 offset → fault AT REST |
| **V27** | **±2048** | **doubled** (cave trampoline) | both 2.0 → match → no fault ✓ |

V27 is the first build with **both halves**. V24 already proved the twin-doubling trampoline mechanism
(Ghidra decoded its `addf.s lp,lp,lp` cave cleanly) — it just lacked the integer widen.

## V27 exact edit set (`builds/v18_v49/build_v27_tva.py`)

**Cal (block #48 + main PN), V18 lineage + corridor widen:**
- GAIN `0xC646C` 891→1782 ; CLAMP `0xC61B4`/`0xC61B2` 512→1024 ; RAMP `0xC64DE` 0x11→0x1B.
- INT corridor dir1 Y `0xC674E`/`0xC6750` +1024→+2048 ; dir2 Y `0xC675A`/`0xC675C` −1024→−2048.
- PN `0x13109`/`0x14120` `'-'→','`.
- `0xC6664` (LERP_B) **LEFT STOCK 1.0** — V26's mistake reverted (asserted unchanged in the build).

**Code (main block) — the new piece, a trampoline into the free `0xC4E00` cave (stock all-`0xFF`):**
- `0x4463A`: `subf.s r2,lp,r10` (`e2ff6254`) → `jr 0xC4E00` (`8807c607`)
- `0xC4E00`: `addf.s lp,lp,lp`    (`ffff60fc`)  ← double dir1 twin
- `0xC4E04`: `addf.s r20,r20,r20` (`f4a760a4`)  ← double dir2 twin
- `0xC4E08`: `subf.s r2,lp,r10`   (`e2ff6254`)  ← displaced dir1 divergence (now `r10 = 2·lp − wall1/1024`)
- `0xC4E0C`: `jr 0x4463e`         (`b70732f8`)  ← return

Doubling lp/r20 reaches the dir1 divergence (in the cave), the dir2 divergence (@0x44662, sees the
already-doubled r20), and the two twin stores (gp-0x6db0/gp-0x6db8 → Monitor 1). At full lock the twin goes
1.0→2.0 to match wall/1024 = 2.0 → Monitor 1 `trunc(2.0×1024)=2048=wall`, Monitor 2 `|2.0−2.0|=0`.
**Monitors stay fully live** (a genuinely wrong corridor LERP still diverges — recalibration to the 2×
design point, not a disable; matches the operator's "do not blind the monitor" directive).

CRC: block #48 `@0xC6FFC`, main `@0xC4FFC`.

## Calibration — proven vs residual

- **[V]:** `0xC6664`=LERP_B (V26's wrong table); the corridor lockstep + both monitor checks; the float
  twins are lp/r20; V27's int+twin doubling matches at full lock; the patch is collateral-free; the built
  image decodes correctly.
- **Residual [the road/bench decides]:** the trampoline doubles the twin EXACTLY (×2) and the cal doubles
  the wall EXACTLY (×2), so the small stock float-vs-int residual `R = (twin − wall/1024)` also doubles
  (→ `2R`) vs the ±5/1024 (Monitor 2) / ±15 LSB (Monitor 1) tolerances. Typically `R` ≪ tolerance, but it
  is **not** measured across all steering angles. **Recommended before flash:** an emulation sweep of
  `(twin − wall/1024)` across velocity/angle on the built image, OR a cautious first drive ready to
  power-cycle. The road test is the true arbiter (`feedback_operator_lived_experience_overrides_analyst_recs`).
